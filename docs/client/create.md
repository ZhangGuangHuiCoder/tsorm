# Create

`create` returns the record actually written and accepts `select`, `include`, and `omit`. Updates are covered in [Update](./update.md), deletes in [Delete](./delete.md).

## Single Record

```ts
const user = await db.user.create({
  data: { email: "alice@example.com", name: "Alice" },
});
```

- An `@auto` primary key is generated by the database and cannot be assigned explicitly.
- Defaults, `uuid()`, `now()`, and typed JSON values are applied the same way as in bulk inserts.
- Nested relation writes, including `connect` and `create`, run in one transaction, see [Relation Writes](./relation-writes.md).
- A unique key that already exists raises `UNIQUE_CONSTRAINT`; use `upsert` to create or update in one call, see [upsert](./update.md#upsert).

## createMany

```ts
const { count } = await db.user.createMany({
  data: [{ email: "a@example.com" }, { email: "b@example.com" }],
  skipDuplicates: true,
});
```

- Accepts only scalar fields; relations are passed through foreign keys. Nested relations and auto-generated IDs are not accepted.
- Defaults, `uuid()`, `now()`, typed JSON, and soft-delete foreign key checks behave the same as a single `create`.
- Uses a multi-row `INSERT`, split into batches under a 900-parameter budget. All batches share one transaction; errors other than unique conflicts skipped by `skipDuplicates` roll back every batch.
- Empty input returns `{ count: 0 }`.
- `count` is the number of records actually inserted. With `skipDuplicates`, unique conflicts (including duplicates within the batch) are not counted, while other validation and foreign key errors still raise.

## createManyAndReturn

```ts
const created = await db.user.createManyAndReturn({
  data: [{ email: "c@example.com" }],
  select: { id: true, email: true },
});
```

- Supports `select`, `include`, `omit`, and virtual fields.
- Return order is not guaranteed; sort by a business key yourself when needed.
- Empty input returns an empty array.

## Database Differences

| Capability            | SQLite                   | PostgreSQL               | MySQL / MariaDB                                          |
| --------------------- | ------------------------ | ------------------------ | -------------------------------------------------------- |
| Multi-row `INSERT`    | Supported                | Supported                | Supported                                                |
| `skipDuplicates`      | `ON CONFLICT DO NOTHING` | `ON CONFLICT DO NOTHING` | Per-row, catching only unique conflicts                  |
| `createManyAndReturn` | `RETURNING`              | `RETURNING`              | Per-row insert and primary-key readback in a transaction |

The MySQL / MariaDB adapter does not use `RETURNING`, so `createManyAndReturn` needs additional statements: auto-generated primary keys use `insertId`, while other records are read back using their supplied single or composite primary key. MySQL does not use `INSERT IGNORE`, to avoid swallowing invalid values, not-null, or foreign key errors.

Unique constraints on soft-deleted models include deleted records, so `skipDuplicates` never restores them. Foreign keys pointing at soft-deleted models must still pass referential validation before deduplication, see [Soft Delete](../schema/soft-delete.md).
